** 说明
typedef void (plug_hello_t)(void); 和 typedef void (*plug_hello_t)(void); 的本质区别在于：
1. 第一种（函数类型）：  
   定义 plug_hello_t 为 函数类型 本身（即：无参数、返回 void 的函数）。  
   - ❌ 不能直接声明变量（C 中不允许函数类型变量）：  
     plug_hello_t f; // 错误：不能定义函数类型变量  
   - ✅ 可用于函数参数/返回类型（会自动调整为指针）：  
          void register_handler(plug_hello_t handler); // 等价于 void register_handler(void (*handler)(void));
     
2. 第二种（函数指针类型）：  
   定义 plug_hello_t 为 指向该函数类型的指针。  
   - ✅ 可直接声明函数指针变量：  
          plug_hello_t fp = my_hello; // 正确：fp 是函数指针
        - ✅ 常用于需要存储/传递函数指针的场景（如回调、事件系统）。
简单说：  
- 第一种定义“函数是什么”，需加 * 得到指针（较少直接用）。  
- 第二种直接定义“函数指针是什么”，可直接用（更常见）。  
在实际代码中，你几乎总是需要第二种形式来声明函数指针变量。  
例如：  
// 常见写法（第二种）：
typedef void (*callback_t)(void);
callback_t cb = some_function;
// 极少见的写法（第一种）：
typedef void callback_t(void); // 定义函数类型
void register_cb(callback_t *cb); // 参数需加 * 得到指针


** hyprland 下拖动应用的方式
由于raylib没有完全适配wayland

在原生 Wayland 中，文件拖放涉及 wl_data_device 协议。raylib 的 LoadDroppedFiles() 依赖于底层窗口库对该协议的封装。

    MIME 类型问题：Wayland 传递的是 URI 列表（通常以 text/uri-list 格式）。

    URL 编码：Wayland 传回的路径通常带有 file:// 前缀，并且会对中文或特殊字符进行百分号编码（如 %20 代表空格）。

如果打印结果是空白、乱码或没有任何输出，通常是因为数据在从合成器（Hyprland）传递到应用的过程中丢失了。

所有要把  musializer 和 文件管理器都使用在终端通过 xwayland运行
具体方式是禁用 Wayland 库加载
在终端运行
env -u WAYLAND_DISPLAY ./musializer
env -u WAYLAND_DISPLAY pacmanfm
